# 學測英文寫作追蹤本

給單一學生使用的學測（GSAT）英文非選擇題（中譯英＋英文作文）寫作弱點追蹤工具。

這份是**公開展示版**，用於分享連結給他人瀏覽，純顯示、不可在網頁上編輯。所有資料的新增與修改都在 Claude 對話中完成，Claude 會產出完整的 `data.json` 讓你直接覆蓋上傳。

## 檔案結構

```
index.html   ← 網頁本體，畫面與邏輯，不含任何學生資料
data.json    ← 所有資料（弱點紀錄、作品集）都在這裡
robots.txt   ← 禁止搜尋引擎爬取
README.md    ← 本文件
.gitignore
```

`index.html` 一載入就會 `fetch('./data.json')` 把資料抓進來渲染，兩個檔案必須放在同一層目錄。

## 四個分頁

| 分頁 | 內容 | 排序依據 |
|---|---|---|
| 弱點追蹤 | 所有弱點條目，點擊有解說的卡片會跳出規則說明彈窗 | `date` 由新到舊 |
| 持續弱點總覽 | 同樣的條目，但用累計次數排序，看得出哪些是主要戰場 | `count` 由多到少 |
| 進步趨勢 | Chart.js 折線圖（分數 /20）＋各篇分數列表 | `date` 由舊到新 |
| 作品集 | 每篇作文，點標題展開原文／批改後版本／備註 | `date` 由新到舊 |

## how to 新增一篇新作文

1. 批改
2. Claude 把這篇整理成 `portfolio` 陣列的一筆，同時累加 `weak` 裡對應的弱點次數、必要時新增弱點類別
3. Claude 直接給你更新後的**完整** `data.json`
4. 把新的 `data.json` 上傳到 GitHub repo，**取代**舊的檔案（GitHub 網頁介面：進到 repo → 點 `data.json` → 右上角鉛筆圖示編輯，或用 Upload files 覆蓋上傳）
5. Commit 之後 Vercel **會自動重新部署**

## data.json 資料格式

```json
{
  "weak": [
    {
      "id": "w0",
      "cat": "類別名稱",
      "desc": "說明（顯示在卡片上）",
      "date": "YYYY-MM-DD",
      "lastSeen": "YYYY-MM-DD",
      "count": 累計出現次數,
      "explain": { ... }
    }
  ],
  "portfolio": [
    {
      "id": "唯一英文代號",
      "title": "作文標題",
      "date": "YYYY-MM-DD",
      "score": 分數（0-20）,
      "prompt": "題目說明",
      "original": "學生原文",
      "corrected": "批改後版本",
      "note": "備註"
    }
  ]
}
```

### `date` 與 `lastSeen` 的語意

`weak` 裡有兩個日期，**不要混用**：

- `date`＝**首次記錄的日期**。建立條目時填一次，之後永遠不動
- `lastSeen`＝**最近一次出現的日期**。弱點每次復發就更新成當天

也就是說，弱點復發時要做三件事：累加 `count`、更新 `lastSeen`、**保持 `date` 不變**。

網頁會拿 `lastSeen` 跟作品集的日期比對，算出「最近一次犯錯之後又寫了幾篇」，顯示成 `最新一篇仍出現`（紅）或 `已 N 篇未出現`（綠），並讓還在犯的弱點排在最前面。用篇數而非天數，是因為批改是按篇進行的。

`lastSeen` 若不存在，程式會自動退回使用 `date`，所以舊格式資料不會壞掉，只是會低估新鮮度。

### `explain` 欄位（選填，決定點擊卡片後彈窗的內容）

沒有 `explain` 的條目不可點擊。有兩種格式：

**A. 規則說明型**（多數條目用這種）

```json
"explain": {
  "rule": "為什麼會錯、怎麼想才對的說明文字",
  "examples": [
    "✗ 錯誤例句 → ✓ 正確例句",
    "✓ 正確用法示範"
  ]
}
```

**B. 字表型**（拼字、相似詞、詞性混淆這類需要條列對照的）

```json
"explain": {
  "type": "wordlist",
  "words": [
    { "wrong": "錯誤拼法", "correct": "正確拼法", "count": 次數, "note": "選填補充" }
  ]
}
```

字表型必須有 `"type": "wordlist"`，程式靠這個欄位判斷要用哪種版面；規則說明型則不需要 `type`。彈窗內的字表會自動依 `count` 由多到少排序。

## 隱私防護

- `robots.txt` 禁止搜尋引擎爬取整站
- `index.html` 的 `<head>` 內含 `<meta name="robots" content="noindex, nofollow, noarchive">`，即使被爬蟲讀到也不會被索引
- 部署時 GitHub repo 名稱與 Vercel 專案名稱都應避免使用任何跟學生、補習班、英文寫作相關的可辨識字眼
